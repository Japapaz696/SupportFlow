# M5 — Suplemento SLA, dashboard e métricas (2026-09-27)

- Tempo corrido simples: opened_at + minutos da política ativa. business_hours_only=true é rejeitado pela API e policies legadas com esse flag não são operacionais, evitando cálculo silencioso incorreto.
- Sem política ativa correspondente à prioridade: 409 SLA_POLICY_NOT_CONFIGURED. Nenhuma duração hardcoded.
- First response: somente primeira resposta pública da equipe (agent/manager/admin). Não contam: requester, comentário interno, atribuição, mudança de status. Respostas posteriores não sobrescrevem first_response_at.
- Resolution: usa resolved_at. Reabertura (resolved -> in_progress) zera resolved_at; prazo original de resolução permanece.
- Estados derivados (não persistidos): pending, at_risk, met, breached. at_risk quando prazo ainda não cumprido e restam <= 20% do tempo total. breached tem precedência.
- Mudança de prioridade: NÃO recalcula deadlines já gravados. SLA é snapshot no momento da criação.
- sla_breached incluído no contrato TypeScript (alinhar ao CHECK do banco). Nenhum evento sla_breached criado automaticamente nesta milestone.
- Políticas SLA: GET /api/v1/sla-policies, POST /api/v1/sla-policies, PATCH /api/v1/sla-policies/:id. RBAC: manager/admin administram; requester/agent não administram. Validação: prioridade, minutos positivos, duplicidade, UUID, campos extras.
- Dashboard: GET /api/v1/dashboard/summary. requester: 403. agent: somente tickets atribuídos a ele OU sem responsável. manager/admin: global. Agregações no PostgreSQL (COUNT/FILTER/GROUP BY/AVG). Sem carregar todos os tickets no JS.
- Relógio injetável: domain/clock.ts (now(), setClock, resetClock) e logic SLA centralizada: domain/sla.ts (computeDueAt, evaluateSlaClock, buildTicketSla). Evita new Date() espalhado.
- Testes M5: banco isolado (TEST_DATABASE_URL / supportflow_test); clock determinístico; cobertura de RBAC, CRUD/validação, duplicidade, política inativa, ticket com/sem política, deadlines server-side, falsificação de deadlines, first response, comentário interno, requester, met/breached/at_risk (limite 20%), resolution, reabertura, dashboard, métricas, taxas, médias, escopo agent, bloqueio requester, isolamento requesters, timezone.
- Nenhum schema change (migrations 001/002 preservadas); não criar 003 sem autorização.
- Sem notificações, e-mail, WhatsApp, WebSocket, IA, anexos, OAuth, refresh tokens, billing, multi-tenant, M6/M7.
- Documentação atualizada: README.md, AGENT_CONTEXT.md, docs/API.md, docs/ARCHITECTURE.md, docs/DATABASE.md, migrations/README.md (002 incluída).
